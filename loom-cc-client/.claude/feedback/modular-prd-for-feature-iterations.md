# 新增功能必须走模块化 PRD 并同步更新 skill 规范

## 背景
用户明确要求：产品正式更名为 Ai陪伴 后，主 PRD 只记录产品大的框架；对话功能、AI课堂、练习/错题本等模块必须独立成文档。以后新增功能时，Agent 也必须按这个规范执行，不能再把模块细节塞回主 Product-Spec。

## 教训
- 新增功能前，先判断它属于产品级框架，还是属于某个具体模块
- 若属于现有模块，应优先修改对应模块文档，不要继续堆到主 PRD
- 若属于新一级模块，应先更新主文档的模块地图，再创建模块文档
- 这个规则不能只改文档，不改 skill；必须同步固化到 `product-spec-builder` 中，否则下次还会犯同样的错

## 执行要求
1. 主文档 `docs/product/current/Product-Spec.md` 只保留产品级内容
2. 模块细节进入 `docs/product/current/modules/*.md`
3. `product-spec-builder` 在迭代模式下必须先判断变更归属层级
4. 文档结构调整后，变更记录与版本归档流程仍然必须执行
